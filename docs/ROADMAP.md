# ShaderBridge Improvement Roadmap

This roadmap decomposes the broader improvement set into independently shippable batches. Each batch keeps ShaderBridge outside game processes and preserves backward compatibility with earlier snapshot formats.

## Batch 1 — Snapshot correctness and lifecycle

Spec: `docs/superpowers/specs/2026-09-28-next-storage-improvements-design.md`

- Stable snapshot reads with bounded retry.
- Atomic manifest publication.
- Import pre-update cache state from active VSS checkpoints.
- Snapshot pin/delete/retention.
- Mark-and-sweep GC with dry-run.
- Logical/physical/dedupe/reclaimable storage statistics.
- VSS startup reconciliation.

## Batch 2 — Incremental tracking and recovery

Goal: stop rescanning and rehashing unchanged caches.

- NTFS USN Journal reader for changed-path discovery.
- FileSystemWatcher remains the live UI feed; USN becomes the durable change source.
- Persist per-volume USN journal ID and last processed USN.
- Detect journal resets/truncation and fall back to a full rescan.
- Incremental snapshots reuse prior manifest entries for unchanged files.
- Dirty-cache baselines triggered by meaningful growth/change thresholds.
- Single-instance store lock and transaction journal.
- Startup recovery for abandoned temporary chunks/manifests/imports/GC.
- Pause background work while a configured game process is active.
- Optional idle-only and low-priority hashing.

## Batch 3 — Game-aware discovery

Goal: stop treating platform shader directories as anonymous blobs.

- Split cache discovery into providers:
  - NVIDIA
  - AMD
  - Intel
  - Windows D3D
  - Steam
  - Custom
- Parse Steam libraries and AppIDs.
- Parse app manifests for installed game names.
- Expose one cache root per Steam AppID when applicable.
- Per-game snapshot/compare/restore selection.
- Per-root exclusions for transient/log/temp files.
- Prepare provider interfaces for Epic/GOG/Xbox/engine-specific detectors.

## Batch 4 — Content-defined storage

Goal: retain dedupe when bytes are inserted/deleted near the front or middle of large cache databases.

- Introduce snapshot format v3.
- Content-defined chunking using a rolling hash / FastCDC-style algorithm implemented in-project.
- Keep v1 whole-file and v2 fixed-4-MiB manifests readable.
- Average chunk target around 4 MiB with bounded minimum/maximum sizes.
- Version the chunking algorithm/parameters in each manifest.
- Sample compressibility and optionally Brotli-compress chunks only when worthwhile.
- Verify chunk hash during restore/store verification.
- Incremental Verify Store with persisted last-verified metadata.

## Batch 5 — Driver and GPU identity

Goal: make compatibility decisions based on more than a driver-version string.

- PCI vendor/device/subsystem IDs.
- Adapter identity/LUID where available.
- Windows build.
- Driver package identity and branch metadata where determinable.
- Vulkan pipeline-cache UUID.
- Detect driver changes via Windows device/registry events instead of polling alone.
- Recognize rollbacks to a previously seen driver environment.

## Batch 6 — Compatibility learning

Goal: preserve only shader work with evidence of reuse value.

- Record per transition:
  - game/AppID
  - cache component
  - GPU identity
  - old driver
  - new driver
  - unchanged/modified/deleted/regenerated bytes
  - restore/migration outcome
- Classify components as:
  - reusable
  - probably reusable
  - driver-native
  - unknown
- Never silently restore based only on learned data; compatibility records inform recommendations/default selections.
- Cache churn analytics and per-game history.
- Show physical storage spent on caches that have never survived a driver transition.

## Batch 7 — Driver-update automation

Goal: reduce manual steps around a GPU-driver install.

- Detect NVIDIA/AMD/Intel/Windows driver-install transitions externally.
- Optional auto-arm VSS before a known installer begins when possible.
- On fingerprint change:
  - reconcile VSS
  - offer/import frozen pre-update state
  - analyze changes
  - create permanent snapshot
  - release checkpoint after user-selected policy
- VSS age/space warnings and configurable limits.
- Never block or modify driver installers.

## Batch 8 — Rebuild/warm-up workflows

Goal: reduce first-launch stutter when a supported application exposes official shader-precompile mechanisms.

- Per-game warm-up profiles using documented executable arguments only.
- No input automation, injection, DLL proxies, or anti-cheat interaction.
- Queue warm-up while idle.
- Track whether a warm-up materially regenerated expected cache files.

## Batch 9 — Store portability and advanced filesystem backends

- Safe store migration between drives.
- Low-space warnings.
- ReFS detection and optional block-clone optimization where appropriate.
- Export/import selected game histories as portable ShaderBridge packages.
- Optional orphan quarantine period before permanent deletion.

## Cross-cutting requirements

- No game-process injection or graphics API hooking.
- No deny-write ACLs/handles against live shader caches.
- Backward-compatible reads for every shipped snapshot format.
- Every destructive operation must have a dry-run or preview where practical.
- CI must build, run the dependency-free storage tests, publish win-x64, and upload the artifact before merge.
